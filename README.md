# 增量归档备份

## 设计目标

- 面向 Linux 文件系统
- 支持增量备份
- 本地任务随时中断不影响本地数据和云端数据最终一致性
- 支持云端自动延迟删除
- 在备份时不需要从云端获取数据？
- 在时间范围内支持云端多版本保存及恢复功能(Time machine-like)
- 支持大文件自动分块上传
- 支持归档级别s3备份后端，index文件除外
- 支持加密备份(optional)
- 保持符号链接
- 保持文件权限
- 保持文件时间
- 保持文件属主、组
- 支持以上配置文件的修改，已有备份不需要重传
- 文件内容与文件元信息分离，重复文件只上传一次

## 逻辑设计

分为同步、一致性校验、个别文件恢复、全量文件恢复四部分。任何步骤可随时打断，打断时云端数据不少于云端index，并可在未来同步中达到最终一致。

### 同步

同步的假设是云端有具有大致一致的index和数据块，扫描本地数据后更新增量部分和新的index，这种场景信任云端index，从而不全量扫描云端 meta 信息，以减少操作次数（以及花费）。注意首次数据同步时云端没有index和文件，满足一致性要求，所以是属于同步逻辑范畴的。这种模式不会进行实际的云端文件删除。

轻量同步逻辑：
1. 检查云端 index hash 和本地 index hash，如果不一致，下载云端 index。此时本地拥有和云端一致的 index 信息
2. 扫描本地目标目录，生产本地 index 信息，可利用旧 index 和云端 index 加速 hash 计算速度
3. 文件操作见附表，生成commit列表
4. 至此收集了所有新信息，并不影响任何云端状态 
5. 上传新文件(overwrite)
6. 上传新的 index 到新的文件名
7. 删除云端旧 index，并把新 index 重命名为主 index

|  新index中是否有  | 云端index中状态   | 操作   |
| --- | --- | --- |
|  是  |  无  | 加入上传队列 |
|  是  |  预删除  | 清除删除标记 |
|  否  |  正常文件  | 标记为未来时间预删除 |

### 一致性校验

一致性将云端信息进行校验，将云端变为一致状态。

强一致性同步逻辑：
1. 对于index中已经超过删除时间的文件，调用删除
2. 扫描云端所有文件信息，云端所有文件记为集合A
3. 文件操作见附表
4. 至此收集了所有新信息，并不影响任何云端状态 
5. 上传新的 index 到新的文件名
6. 删除云端旧 index，并把新 index 重命名为主 index

|  index中是否有  | 云端文件集合中是否有 | 操作 |
| --- | --- | --- |
| 是 | 是 | 无 |
| 是 | 否 | 文件丢失，删除index条目 |
| 否 | 是 | 生产lost_found条目 |
