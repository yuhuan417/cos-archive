# 增量归档备份

## 设计目标

- 面向 Linux 文件系统
- 支持增量备份
- 本地任务随时中断不影响本地数据和云端数据最终一致性
- 支持云端自动延迟删除
- 在备份时不需要从云端获取数据？
- 在时间范围内支持云端多版本保存及恢复功能(Time machine-like)
- 支持大文件自动分块上传
- 支持归档级别s3备份后端，index文件除外
- 支持加密备份(optional)
- 保持符号链接
- 保持文件权限
- 保持文件时间
- 保持文件属主、组
- 支持以上配置文件的修改，已有备份不需要重传
- 文件内容与文件元信息分离，重复文件只上传一次

## 逻辑设计

分为轻量同步、强一致性同步、个别文件恢复、全量文件恢复四部分。任何步骤可随时打断，打断时云端数据不少于云端index，并可在未来同步中达到最终一致。

### 轻量同步

轻量同步的假设是云端有具有大致一致的index和数据块，扫描本地数据后更新增量部分和新的index，和强一致性同步的区别在于这种场景信任云端index，从而不全量扫描云端 meta 信息，以减少操作次数（以及花费）。注意首次数据同步时云端没有index和文件，满足一致性要求，所以是属于轻量同步逻辑范畴的。

轻量同步逻辑：
1. 检查云端 index hash 和本地 index hash，如果不一致，下载云端 index。此时本地拥有和云端一致的 index 信息
2. 对于云端 index 中标记为待删除的文件，调用删除
3. 扫描本地目标目录，生产本地 index 信息，可利用旧 index 和云端 index 加速 hash 计算速度
4. 文件操作见附表
5. 至此收集了所有新信息，并不影响任何云端状态 
6. 上传新文件(overwrite)
7. 上传新的 index 到新的文件名
8. 删除云端旧 index，并把新 index 重命名为主 index
9. 对于需要标记删除的文件，调用删除

|  新index中是否有  | 云端index中是否有   | 操作   |
| --- | --- | --- |
|  是  |  否  | 加入上传队列 |
|  否  |  是，正常文件  | 获取云端信息，标记为未来时间预删除 |
|  否  |  是，已标记为预删除  | 获取云端信息，如果已经超时，标记为待删除 |



### 强一致性同步

强一致性同步的假设是参照云端 index 和文件 meta 信息，在尽量减少重复上传的基础上，扫描本地数据后更新增量部分并修正 index，和轻量同步的区别在于这种场景不假设云端 index 和文件信息是一致的。实现区别为，以云端扫描信息为准，而非云端index为准。

强一致性同步逻辑：
1. 检查云端 index hash 和本地 index hash，如果不一致，下载云端 index。此时本地拥有和云端一致的 index 信息
2. 虽然不信任云端 index，但已经被标记待删除的文件还是可以安全删除，对于云端 index 中标记为待删除的文件，调用删除
3. 扫描本地目标目录，生产本地 index 信息，为保证强一致性，不利用云端和旧 index 加速 hash 计算速度
4. 扫描云端所有文件信息，云端所有文件记为集合A
5. 文件操作见附表
6. 至此收集了所有新信息，并不影响任何云端状态 
7. 上传新文件(overwrite)
8. 上传新的 index 到新的文件名
9. 删除云端旧 index，并把新 index 重命名为主 index
10. 对于需要标记删除的文件，调用删除

|  新index中是否有  | 云端文件集合中是否有 | 操作 |
| --- | --- | --- |
| 是 | 是 | 无 |
| 是 | 否 | 上传 |
| 否 | 是 | 标记为未来时间待删除 |
